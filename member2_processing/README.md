# Niya: Big Data Processing

## 1. Objective

Process historical river observations using Hadoop MapReduce and analyze rainfall and elevation data using Apache Spark.

## 2. Technology Stack

- Python
- Hadoop 3.5.0
- HDFS and Hadoop Streaming
- Apache Spark 3.5.9
- Rasterio, NumPy and Pandas
- GeoTIFF and CSV

Spark runs in local mode on a single machine.

## 3. Input Datasets

### River Observations

Local path:

`member1_data/data/processed/river_clean.csv`

HDFS path:

`/user/niya/flood-risk-analysis/input/river/river_clean.csv`

Number of observations: 465,076.

The cleaned river dataset covers May 29, 2021, through March 10, 2025.

### Rainfall Data

Directory:

`member1_data/data/processed/rainfall_kerala/`

Contains 14 daily rainfall GeoTIFF files covering **September 21–October 4, 2024**, derived from NASA GPM IMERG V07B data.

Each cropped rainfall raster contains 2,000 grid cells.

### Elevation Data

File:

`member1_data/data/processed/elevation/elevation_kerala_bbox.tif`

The elevation raster provides terrain information used in the rainfall/elevation processing pipeline.

## 4. Hadoop MapReduce

### Mapper

File: `member2_processing/mapreduce/mapper.py`

The mapper reads river observations and extracts station, district, date, water level, latitude and longitude.

It groups observations using station, district and date as the key.

### Reducer

File: `member2_processing/mapreduce/reducer.py`

The reducer calculates the following daily station statistics:

- Number of observations
- Average water level
- Minimum water level
- Maximum water level

Latitude and longitude are also included in the output.

### Output

HDFS:

`/user/niya/flood-risk-analysis/output/river_daily_summary/`

Local:

`results/mapreduce/river_daily_summary.tsv`

The output contains 12,648 daily station summaries.

The output is tab-separated and contains nine columns:

Station, district, date, count, average water level, minimum water level, maximum water level, latitude and longitude.

## 5. Apache Spark Processing

Script:

`member2_processing/spark/process_rainfall_elevation.py`

### Processing Methodology

1. Read the daily rainfall GeoTIFF files.
2. Read the elevation GeoTIFF.
3. Validate the coordinate reference systems, raster bounds and expected dimensions.
4. Aggregate elevation pixels into 120 × 120 pixel blocks.
5. Calculate elevation statistics for each rainfall grid cell.
6. Create Spark DataFrames for rainfall and elevation.
7. Join the DataFrames using grid row and column.
8. Calculate daily rainfall and elevation statistics.
9. Export the combined records to CSV.

Spark executes in local mode using `local[*]`.

### Output

Directory:

`results/spark/rainfall_elevation_sep_oct_2024/`

The output is a Spark CSV directory containing one or more part files and a `_SUCCESS` marker.

The CSV includes the rainfall date, grid coordinates, rainfall values, elevation coverage counts and elevation statistics.

**Total records: 28,000**, representing 2,000 grid cells over 14 days.

### Daily Rainfall Summary

The analysis period is September 21–October 4, 2024.

Daily mean and maximum rainfall statistics are generated by the processing pipeline. Refer to the current Spark output and Member 3's rainfall analysis results for the computed values.

## 6. Data Quality and Limitations

River observations range from May 29, 2021, to March 10, 2025. Rainfall data covers September 21–October 4, 2024.

The rainfall period falls within the overall date range of the river dataset. However, the actual number of river observations during those 14 days must be checked before drawing conclusions from same-date comparisons.

The elevation raster contains 28,800,000 pixels, of which 8,644,800 (approximately 30.02%) are NoData.

Of the 2,000 rainfall-grid cells:

- 560 have entirely missing elevation.
- 119 have partially missing elevation.
- 1,321 have complete elevation coverage.

Missing elevation must not be interpreted as zero. Valid zero-valued pixels require separate consideration.

The rainfall and elevation grids have slightly different origins. The current implementation uses fixed 120 × 120 elevation blocks. Spatial alignment should therefore be considered before detailed geographical interpretation.

These pipelines perform data processing and descriptive analysis. They do not constitute a validated flood prediction model.

## 7. Reproduction

Run commands from the project root.

### Spark

Activate the Python environment and execute:

```bash
spark-submit member2_processing/spark/process_rainfall_elevation.py
```

The input datasets must be available at the paths listed in Section 3.

The script writes its output to:

`results/spark/rainfall_elevation_sep_oct_2024/`

### Hadoop MapReduce

Requirements:

- Hadoop 3.5.0 configured and running.
- HDFS and YARN services running.
- The cleaned river CSV uploaded to the HDFS input path.
- Hadoop Streaming JAR available.

Set the Streaming JAR path:

```bash
export STREAMING_JAR="$HADOOP_HOME/share/hadoop/tools/lib/hadoop-streaming-3.5.0.jar"
```

Check the HDFS input file:

```bash
hdfs dfs -ls /user/niya/flood-risk-analysis/input/river/river_clean.csv
```

Before rerunning the job, remove the previous output directory if it exists:

```bash
hdfs dfs -rm -r /user/niya/flood-risk-analysis/output/river_daily_summary
```

Run Hadoop Streaming from the project root:

```bash
hadoop jar "$STREAMING_JAR" \
  -files member2_processing/mapreduce/mapper.py,member2_processing/mapreduce/reducer.py \
  -mapper "python3 mapper.py" \
  -reducer "python3 reducer.py" \
  -input /user/niya/flood-risk-analysis/input/river/river_clean.csv \
  -output /user/niya/flood-risk-analysis/output/river_daily_summary
```

Verify successful completion:

```bash
hdfs dfs -test -e /user/niya/flood-risk-analysis/output/river_daily_summary/_SUCCESS \
  && echo "MapReduce SUCCESS" \
  || echo "MapReduce OUTPUT NOT VERIFIED"
```

Download the output:

```bash
mkdir -p results/mapreduce

hdfs dfs -get \
  /user/niya/flood-risk-analysis/output/river_daily_summary/part-00000 \
  results/mapreduce/river_daily_summary.tsv
```
