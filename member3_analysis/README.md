# Parvathy: MongoDB, Analysis, and Visualization

## 1. Objective

The objective of Member 3 is to implement the database, analysis, and visualization layer of the Big Data-Based Spatiotemporal Flood Risk Analysis project.

This module receives the processed outputs generated by Hadoop MapReduce and Apache Spark, stores them in MongoDB, performs statistical analysis, and generates JSON reports and visualizations.

The main responsibilities are:

- Import processed river and rainfall/elevation data into MongoDB.
- Query and analyze river water-level summaries.
- Analyze daily rainfall patterns and elevation-data completeness.
- Generate combined analysis reports.
- Visualize the results using charts, heatmaps, and a combined dashboard.
- Document data-quality issues and limitations affecting flood-risk interpretation.

**Note:** The current implementation performs descriptive analysis and preliminary screening. It does not constitute a validated flood-prediction model.

`member3_analysis/mongodb/connection.py`

`member3_analysis/mongodb/import_data.py`

This database layer makes the processed outputs available to the subsequent analysis scripts.

## 5. Statistical Analysis

The analysis module is located in `member3_analysis/analysis/`.

### 5.1 River Analysis

Script: `river_analysis.py`

The river analysis examines the available river-summary records and generates statistics at district and station levels.

The analysis includes:

- District-level average, minimum, and maximum values.
- Station-level summary statistics.
- Record counts and station counts.
- Identification of stations with comparatively high maximum values using a relative statistical threshold.

Output:

`member3_analysis/analysis/output/river_analysis.json`

The relative threshold is based on the available dataset. It is not an official station-specific flood-warning threshold.

### 5.2 Rainfall and Elevation Analysis

Script: `rainfall_analysis.py`

The rainfall analysis examines rainfall variations across the available dates and grid cells.

The analysis includes:

- Daily average, minimum, and maximum rainfall.
- Identification of grid records with high rainfall values.
- A configurable 100 mm maximum-rainfall screening threshold.
- Identification of the highest-rainfall grid cells.
- Assessment of elevation-data completeness.

Output:

`member3_analysis/analysis/output/rainfall_analysis.json`

The 100 mm threshold is used for exploratory screening and should not be interpreted as an official flood-warning criterion.

### 5.3 Combined Analysis

Script: `combined_analysis.py`

The combined analysis consolidates the outputs of the river and rainfall analyses.

It includes:

- River-level indicators and station summaries.
- Daily rainfall summaries.
- Rainfall screening results.
- Elevation-data quality statistics.
- Interpretation notes and known limitations.

Output:

`member3_analysis/analysis/output/combined_risk_assessment.json`

The combined report does not calculate a validated flood-risk probability or a single combined risk score because the available river and rainfall datasets do not have overlapping observation dates.

## 7. Data Quality and Limitations

The following limitations affect the interpretation of the current analysis.

- **Different observation periods:** The river-summary data covers 29 May 2021 to 10 March 2025, while the rainfall/elevation grid covers 1–4 August 2025. There are no overlapping observation dates.
- **Limited rainfall coverage:** Four days of rainfall data are insufficient to establish robust seasonal patterns or validate a flood-prediction model.
- **Coordinate verification:** The Spark output appears to have latitude and longitude assigned in the opposite order. This must be verified before interpreting the grid visualizations geographically.
- **Missing elevation data:** Some grid records contain missing elevation pixels. These missing values require further investigation before geographical conclusions can be drawn.
- **Relative river-level screening:** Stations are identified using relative statistical values rather than verified, station-specific official warning thresholds.
- **Exploratory rainfall threshold:** The 100 mm threshold is a screening parameter, not an official local flood-warning criterion.
- **No validated combined risk score:** The current analysis is descriptive and does not produce a calibrated flood-risk probability.
- **Spatial coverage:** The rainfall/elevation grid and its coordinates must be verified against the intended Kerala study area before drawing strong geographical conclusions.

These limitations should be considered before extending the current analysis into a predictive flood-risk assessment.

## 8. Reproduction

Run the commands from the repository root with the Python virtual environment activated and MongoDB running.

### Step 1: Activate the environment

```bash
source .venv/bin/activate
```

### Step 2: Import the processed datasets

```bash
python -m member3_analysis.mongodb.import_data
```

This imports the river-summary and rainfall/elevation outputs into MongoDB.

### Step 3: Run river analysis

```bash
python -m member3_analysis.analysis.river_analysis
```

### Step 4: Run rainfall and elevation analysis

```bash
python -m member3_analysis.analysis.rainfall_analysis
```

### Step 5: Generate the combined analysis report

```bash
python -m member3_analysis.analysis.combined_analysis
```

### Step 6: Generate the individual visualizations

```bash
python -m member3_analysis.visualization.river_graphs
python -m member3_analysis.visualization.rainfall_graphs
python -m member3_analysis.visualization.maps
```

### Step 7: Generate the combined dashboard

```bash
python -m member3_analysis.visualization.combined_visualization
```

The JSON reports are generated under `member3_analysis/analysis/output/`, and the PNG visualizations are generated under `member3_analysis/visualization/output/`.

To open the combined dashboard on Ubuntu:

```bash
xdg-open member3_analysis/visualization/output/combined_risk_dashboard.png
```

**Prerequisites:** MongoDB must be running, the required Python packages must be installed, and both upstream data files must be available at their configured paths. Re-importing data should follow the import script's collection-handling behavior to avoid unintended duplicate records.
